# 日常出账流程（每日制）

## 节奏定义

**默认每日出账**，只处理过去 24 小时增量。周日额外补发全周汇总与上周对比。
周记录卡不是"每周才出一次"，而是**每天往当周卡里追加**，历史周卡保持收起。

## 触发方式

- 自动：定时任务到点触发（默认每日 09:00）
- 手动：用户说"出账/更新账本/记账"
- 回溯查询：用户问"我当时为什么这么决定"（只读，不写账）

## 八步流程（顺序不可跳）

### 1. 读事实源

读 `项目登记表.md`。**项目状态只认登记表**，不得根据文件变动推断"项目已完成/已烂尾"。发现登记表与实际明显冲突时列入简报请用户确认，不自行改写。

### 2. 扫描增量

```bash
python3 scripts/scan_changes.py --root <扫描根> --since-hours <距上次出账的小时数>
```

只看变动，不重扫全量。某项目无变动则**不动它的卡**（避免每天重写全部内容）。

对话变动单独处理：探测宿主的对话记录目录（**不要硬编码路径，各宿主不同**），找出新增对话，提取其中的决策与转折。

### 3. 写条目

按 `三层记录与标签规范.md` 写：事实层 → 思路层 → 变化层，打标签（`.tag` + `.g-adv/.g-turn/.g-dec/.g-ver/.g-les/.g-stuck`），项目卡状态用 `.badge`（`.b-run/.b-iter/.b-dep/.b-block/.b-review/.b-todo/.b-q`）。

**思路层来源优先级**：本次对话中的用户口述 > 历史对话中的明确表述 > 记忆还原（标"（记忆还原）"） > 无法还原（标"思路待补"）。**严禁编造。**

### 4. 同步两个文件（最常见的失败点）

- `项目登记表.md` / `交付台账.md` = 数据源，机器读写
- `账本.html` = 阅读视图，人看的那一份

**每次改完数据源，必须在同一次操作里刷 HTML。** 历史教训：曾只改 md 没刷 HTML，账本网页停留在旧内容，用户完全不知道发生了什么。若内容过多无法一次刷完，至少先刷已完成部分并在简报中说明"部分已更新"。

### 5. 渲染 HTML

- 只改数据，**禁止改动皮肤 CSS 与结构类名**
- 九个板块顺序与类名见 SKILL.md「账本结构」
- 新增项目卡时复制现有同类卡片结构，套 `.card` + `.wob1/.wob2/.wob3`
- 周记录卡：当周卡置于最上方且 `open`，历史卡去掉 `open`
- 统计条四个数字同步更新（登记项目／待补录／待你拍板／风险预警）
- 保持单文件、内联 CSS、手机可读

### 6. 更新四个判断板块

| 板块 | 更新规则 |
|---|---|
| 待你拍板 | 新增需用户决策的问题；标注「⚠连续 N 期未动」 |
| 风险预警 | 分级（高／中／低）；新发现标「·新」；写清触发条件与已发生事实 |
| AI 建议 | 每条含 `.act`（问题与动作）+ `.fact`（事实依据与出处） |
| 待归类 | 三列表：事项／事实依据／为什么无法归类 |

**分类守护**：无法归入现有类目的产出列入"待归类"，在简报中逐条请用户定位，**不强行归类**；同类未归类项连续出现 2 次以上时**提议**新增类目，用户确认后才入表。

**待拍板升级**：连续 3 期未动的待拍板项升级为风险预警并注明，但**不催促、不追问原因**。

### 7. 项目卡内的行动出口

行动出口写在**每张项目卡的 `.next` 里**（「下一步：…」），不设全局任务板、不设"本周必做一件事"板块。
理由：账本是镜子不是任务引擎；镜子替人安排日程会越界，而"这个项目接下来做什么"属于项目本身。

### 8. 简报（每日不超过 6 行）

```
昨日新增：N 条，涉及 X 个项目
要点：（一句话，最重要的决策或转向）
待归类：N 项（逐条列出，请定位）
待拍板：N 项
需补思路层：N 处
```

**周日**额外加发本周汇总与上周对比（决策数、转向数、能力卡片产出）。

## 周日加发内容

- 当周周卡补齐统计与摘要
- 与上周对比：决策数、转向数、待拍板增减、能力卡片进度
- 允许出现趋势性观察（如"连续 3 周有想法无执行"），且**必须交用户确认定性**，不得由 AI 直接下judgment

## 发布（可选）

用户要求上线时才执行：读 `发布信息.md`，用宿主的站点部署能力以同一目录重新部署（复用既有应用与链接）。发布是**可选项**，不得默认开启。部署失败则保留本地更新并在简报中如实说明。

## 禁止事项

- 禁止评分、排名、"本周成长几分"
- 禁止代填用户未表达的思路
- 禁止把一次推迟判定为失信
- 禁止在 HTML 里改皮肤 CSS 或板块结构
- 禁止只改 md 不刷 HTML
- 禁止凑数式的 AI 建议（无问题时写明"本期未发现需纠正项"）
- 禁止新增全局任务板 / "必做一件事"板块
