# 安装向导与冷启动回填 · Install Guide & Cold Start

首次启用必须走完本流程。**顺序不可颠倒，跳过冷启动等于让用户第一天就面对空账本——这是本 skill 最大的死亡谷。**

## 第一步：安装向导（一次约 5 分钟）

用 `AskUserQuestion` 或逐条问答，一次只问1-2 个问题，不要一次抛六个。

### Q1 账本主人与名称

问：账本主人怎么称呼？账本叫什么名字？
- 主人名用于账本落款与"我的"视角
- 默认建议名：`经验账本`；若用户已有习惯命名（工作台、复盘本等）则尊重用户命名

### Q2 分类框架（关键，类目所有权归用户）

问：你的事情分成哪几类？

- **不要替用户设计类目**。给出提问而非选项，但可举一个格式示例：`<一级分类>/<二级分类>`，例如"工作服务/市场部""个人经营/小程序"
- 若用户回答"你帮我定"，则先给2-3 套候选框架让其选，选完写入 `项目登记表.md` 顶部并标注"由 AI 提议、用户确认"
- **记录一条元规则**："分类框架由用户定义，AI 无权增删改类目"，写入登记表顶部

### Q3 扫描范围

问：账本要扫描哪些范围？

- 至少包含：主要工作空间目录、项目文件夹
- 必须包含：AI 对话记录所在目录（用于冷启动回填与工时核算；不同宿主路径不同，需现场探测而非猜测）
- 明确告知：账本会读取范围内的文件变动与对话，**只存本地**；用户可随时排除任一路径或整体删除

### Q4 出账频率与时间

问：多久出一次账？几点？

- 默认建议：工作日早晨 09:00（回顾昨天）或每周日晚（回顾一周）
- 出账越频繁，单次内容越少、越轻
- 用宿主定时能力创建自动化任务；宿主无定时能力时如实说明"需要你主动说来出账"，**不得承诺自动运行**

### Q5 账本皮肤

问：账本想要什么视觉风格？

给出五个选项（handdrawn 手绘 / minimal 极简 / business 商务 / dopamine 多巴胺 / tech 科技），每个附一句气质说明。默认 handdrawn。

### Q6 是否启用交付层

问：是否需要交付层（SOW 模板 / 能力卡片 / 工时账 / 报价校准）？

- 面向个人复盘的创作者 → 建议关闭，保持轻量
- 面向接单交付的自由职业者/顾问 → 建议开启
- 关闭时明确说明："能力卡片"仍会作为提炼层的一部分存在，只是不带 SOW 与报价模块

### 收尾确认

复述全部配置（分类框架、扫描范围、出账时间、皮肤、交付层），请用户确认后再落盘。

## 第二步：冷启动回填

目的：**让用户第一次打开账本就看到内容**，而不是一个空壳。

### 采集

1. 跑 `scripts/scan_changes.py --root <扫描根> --since-hours 720`（默认回看30 天）
2. 采集对话记录：列出宿主对话记录目录，按时间倒序读取标题与关键内容
3. 用 `scripts/calc_worktime.py` 对识别出的主要项目跑一遍工时，得到真实数据

### 起草

1. 写 `项目登记表.md`：分类框架 + 扫描出的项目清单（项目名、所属类目、状态一律标**待确认**）
2. 写时间轴条目：只写**事实层**（能确证的），思路层一律标"思路待补"，来自记忆的可标"（记忆还原）"
3. 交付层启用时，用真实工时填工时账首行

### 确认（不可跳过）

把起草结果交给用户：

- 逐项目请其确认：**这个项目属于哪个类目？状态对不对？有没有漏掉的项目？**
- 明确告知："我已把无法还原的思路层标为待补，共 N 处，你可以在任意时刻补，也可以永远不补——账本不会因此催你"
- 用户确认后才写入 `账本.html`

## 第三步：交付物与自动化

1. 用 `scripts/new_ledger.py` 生成账本目录与三件套（传入已确认的分类框架与皮肤）
2. 若宿主支持定时任务，创建出账自动化，提示词必须包含：
   - 三层记录规范与标签词典的引用
   - 五条防翻车铁律
   - md 与 HTML 必须同步
   - 只改数据禁止改CSS
   - 出账收尾必须给"只改一件事"
3. 向用户交付：**账本本地路径、线上链接（若发布）、自动化下次执行时间**，并说明怎么用一句话触发手动出账

## 冷启动的质量红线

- **不编**：没有依据的项目宁可不写，不可推测
- **不捧**：起草说明只报事实与不确定项
- **不催**：不得在冷启动阶段就要求用户"尽快补齐思路层"
- **不删**：任何回填内容出错，用户要求即改，不做二次审判
